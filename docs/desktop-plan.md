# Quotr desktop: plan

Quotr runs as a macOS app built with [Electrobun](https://docs.electrobun.dev/electrobun/) 2.0.6. The React UI is unchanged. A small Bun main process owns the window and does everything that touches the Mac: saving files, file dialogs and PDFs.

## How it fits together

```
bun scripts/build.ts ──► dist/ ──(build.copy)──► views://mainview/index.html   (native WebKit)
                                                        │ typed RPC (src/shared/rpc.ts)
src/bun/index.ts  ◄─────────────────────────────────────┘
  ├─ workspaceFiles.ts   JSON files in the app's data folder (auto-save)
  └─ exports.ts          folder dialog, .quotr/backup export, PDFs via installed Chrome
```

- **Webview:** the existing Bun and Tailwind build outputs to `dist/`, which is copied into the app bundle. This is the official `react-tailwind-vite` template's pattern, with Bun's bundler in place of Vite.
- **Main process:**
  - Opens the window and sets the standard macOS menus, including Edit, so ⌘C, ⌘V, ⌘Z and ⌘A work.
  - Answers six RPC requests: load, save, open file, export file, export PDF and copy text.
- **Hot reload:** with `bun run hmr` running, dev builds load `http://localhost:5180` (the template's dev-server check). Without it, they load the bundled files.
- **Desktop only:** opened in a normal browser, the page says Quotr is a desktop app. It offers to download any data the old browser version left behind, as a backup to restore in the app.

## Decisions

| Topic | Decision | Why |
| --- | --- | --- |
| Renderer | Native WebKit (`bundleCEF: false`) | The app stays small: the DMG is 33 MB, against about 400 MB with Chromium. |
| PDFs | Installed Google Chrome, headless `--print-to-pdf` | WebKit's print engine shrank the page and cut a line in half at a page break. Paged.js crashed on Tailwind v4 CSS. Chrome's output matched the browser version's PDFs exactly. |
| Data folder | `~/Library/Application Support/com.neohaggard.quotr/<channel>/` | The macOS standard. Electrobun keeps a separate folder per channel (`dev`, `stable`). |
| Identifier | `com.neohaggard.quotr` | Permanent, because it names the data folder and the signing identity. |
| `.quotr` files | Import and export only | Saving is automatic. "Import file…" stays, and "Export .quotr file…" is under More actions. |
| Exports | The native choose-folder dialog opens every time | It starts in the last folder used (saved in `prefs.json`), and never overwrites: a clash gets " (2)". |

## Automatic saving

```
<data folder>/
  settings.json        business profile and defaults
  clients.json
  quotes/<id>.json     one file per quote
  invoices/<id>.json   one file per invoice
  prefs.json           last export folder
```

- `store.tsx` loads the workspace over RPC at start-up and saves 250 ms after each change.
- The main process compares each file with what it last wrote and rewrites only the files that changed.
- Every write goes to a temp file first, then is renamed into place.
- Deleting a document deletes its file. File names are sanitised.

## Electrobun setup

These follow the 2.0.6 templates and docs.

- `electrobun@2.0.6` dev dependency, also pinned in `hutch.config.ts`. That file's tasks match the `package.json` scripts, so no global `hutch` is needed.
- `electrobun.config.ts`:
  - `mainProcess: "bun"` set explicitly.
  - `copy` and `watchIgnore` set for `dist/`.
  - `icons: "icon.iconset"`: 16 to 512 px, each at @1x and @2x, generated from the Quotr mark.
  - `codesign` and `notarize` off.
- `tsconfig.json` maps `electrobun`, `electrobun/bun` and `electrobun/view` to `.hutch/devkit`.
- `.gitignore` covers `.hutch/`, `build/` and `artifacts/`.
- `.hutch/` is generated by `electrobun prepare`, which every script runs first.

## Not done yet

- **Signing:** needs an Apple Developer ID, with credentials in environment variables. Until then, other Macs will warn when opening the app.
- **Auto-update:** needs `release.baseUrl`, where the update files are hosted.
- **Chrome dependency:** PDFs need Google Chrome installed. Without it, Download PDF shows a message saying so.
